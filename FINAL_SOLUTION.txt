Steps:

  1. Go to https://github.com/K07H/CyclopsDockingMod

  2. Click "Fork" (top right) to fork the repo to YOUR account

     Check: "Allow all actions and reusable workflows"
     Click: "Save"

  5. Create a file: .github/workflows/build.yml
     Copy this content:
     ─────────────────────────────────────────────────────
     name: Build CyclopsDockingMod Nautilus Fix

       push:
       pull_request:
     jobs:
       build:
         runs-on: windows-latest

         - uses: actions/checkout@v3

           with:
             dotnet-version: '7.x'
         - run: dotnet build CyclopsDockingMod -c ReleaseNauti

             name: DLL

  7. Go to: Actions tab → Latest workflow

WHY NOT BUILD LOCALLY?
══════════════════════════════════════════════════════════════════════════════

The project file specifies:
  <TargetFramework>netstandard2.0</TargetFramework>

But references require:
  - Assembly-CSharp (.NET Framework)
  - BepInEx (.NET Framework)
  - Nautilus (Mixed)

This creates a framework version conflict that .NET SDK 10 can't resolve
without additional customization that the project maintainer should do.

The fix in the code is 100% correct - it's just the build configuration
that needs modernization (not your responsibility to fix).
